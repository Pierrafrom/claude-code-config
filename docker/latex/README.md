# LaTeX compilation image — `cours-latex`

Self-contained TeX Live toolchain used by the `cours-latex` skill
(`skills/cours-latex/SKILL.md`) to compile course-notes repos generated
from `examples/latex-*` — no local TeX Live/Python/Pygments installation
required, on either WSL2 or Windows, as long as Docker Desktop is running
with its WSL2 integration enabled for the distro in use.

## What's in the image

- `texlive/texlive:latest-full` — full TeX Live scheme (LuaLaTeX,
  `latexmk`, TikZ/pgfplots, tcolorbox, glossaries, KOMA-Script, ...).
- `python3-pygments` — required by the `minted` package (already bundled
  by the base image; pinned explicitly so a future rebuild can't drop it).
- `poppler-utils` (`pdftotext`, `pdfimages`, `pdftoppm`) — PDF text/image
  extraction used by the skill before writing LaTeX.
- `fonts-firacode` — code font loaded via `fontspec` in
  `examples/latex-preamble.sty`. The full TeX Live scheme already ships
  the complete **Libertinus** family (Serif/Sans/Mono/Math) used for body
  text and `unicode-math` — no separate apt package needed for it.

## Build

```bash
docker build -t cours-latex:latest docker/latex/
```

Rebuild whenever `texlive/texlive:latest-full` gets a new TeX Live release
you want, or after editing this Dockerfile — the tag is intentionally
floating (see the deviation note in the skill's plan/guardrails), not
pinned by digest, since this is a local single-user dev tool, not a
deployed service.

## Verify after building

```bash
docker run --rm cours-latex:latest lualatex --version
docker run --rm cours-latex:latest python3 -c "import pygments; print(pygments.__version__)"
docker run --rm cours-latex:latest pdftotext -v
docker run --rm cours-latex:latest fc-list | grep -i libertinus
docker run --rm cours-latex:latest fc-list | grep -i "fira code"
```

If a font name reported by `fc-list` doesn't match what
`examples/latex-preamble.sty` expects in `\setmainfont`/`\setsansfont`/
`\setmonofont`, fix the `.sty` file to match the name actually registered
by fontconfig rather than the apt package name.

## Usage

Not run directly — each course repo generated by the `cours-latex` skill
gets its own `compile.sh` (Bash/WSL) and `compile.ps1` (PowerShell)
wrapper, copied from `examples/`, that call this image by tag:

```bash
docker run --rm -v "$(pwd):/workspace" -w /workspace cours-latex:latest \
  latexmk -lualatex -shell-escape -interaction=nonstopmode -halt-on-error main.tex
```

`-shell-escape` is required by `minted`. No `ENTRYPOINT`/`CMD` is set on
the image on purpose — the wrapper scripts pass the full command
(`latexmk`, `pdftotext`, `pdfimages`, or a shell for debugging) each time.

## Editing with VS Code

The `cours-latex` skill copies `examples/latex-vscode-settings.json` →
`.vscode/settings.json` and `examples/latex-vscode.code-snippets` →
`.vscode/cours-latex.code-snippets` into every scaffolded course repo.
Install:

- **LaTeX Workshop** (`James-Yu.latex-workshop`) — compilation, SyncTeX,
  the built-in PDF viewer.
- **LTeX** (`valentjn.vscode-ltex`) — French grammar/spell-checking
  inside `.tex` files (the settings file sets `ltex.language: fr`).
- **WSL** (`ms-vscode-remote.remote-wsl`) — only needed when the course
  repo lives under a WSL2 path (e.g. `~/Code/cours-*`) rather than a
  native Windows path — opens VS Code's server inside WSL2 so `docker`
  resolves to Docker Desktop's WSL integration instead of the Windows
  side. Same `settings.json` works unchanged either way, since both
  sides share one Docker Desktop engine (confirmed: `docker context ls`
  shows the same `desktop-linux` context from both PowerShell and WSL2).

The settings file enables LaTeX Workshop's native Docker support
(`latex-workshop.docker.enabled` + `latex-workshop.docker.image.latex:
"cours-latex:latest"`) rather than a hand-rolled `docker run` recipe —
the officially supported mechanism, per
`rules/common/config-standards.md`'s "extend the official baseline"
principle. **Important**: the custom `latexmk-cours` tool defined there
deliberately omits `-pdf`/`-lualatex` — LaTeX Workshop's *default*
recipe passes `-pdf`, which would override the course repo's own
`.latexmkrc` (`$pdf_mode=4`, LuaLaTeX) and silently fall back to
pdflatex, breaking `fontspec`/`unicode-math`/`minted`.

**Known limitation**: LaTeX Workshop has an open upstream issue with
SyncTeX (PDF↔source jump) for source files in a subdirectory when
compiling via Docker — course chapters live under `chapitres/`, so
forward/inverse search may not resolve correctly for chapter files even
though it works for `main.tex`. Not fixed on this end; tracked upstream
at [James-Yu/LaTeX-Workshop#2107](https://github.com/James-Yu/LaTeX-Workshop/issues/2107).

**Not verified interactively**: the JSON/JSONC in both template files
was validated for syntax (parses cleanly), but the actual VS Code
compile-on-save/SyncTeX/snippet behavior has not been click-tested in a
running VS Code instance — this environment has no way to drive the VS
Code GUI. Confirm the build recipe and SyncTeX behavior yourself on
first use.

## Verified end-to-end (2026-09-09)

A full test compile (definition/theorem/example/remark/intuition boxes,
a `proof` environment, a TikZ automaton, a `minted` Python listing, one
glossary entry, French babel typography) went through `latexmk` cleanly:
no `LaTeX Error`, no `!`-prefixed fatal error. Two informational warnings
remain and are expected/benign — safe to ignore:

- `Package french.ldf Warning: You are relying on the legacy list code.` —
  babel-french's own forward-looking notice about a future default list
  format; current behavior is correct.
- `Package tracklang Warning: No 'datatool' support for dialect 'french'` —
  a glossaries-internal dependency (`datatool`) lacking French locale
  data; does not affect glossary output (verified: entries and the
  translated "Glossaire" heading/ToC entry render correctly).

Two fixes worth knowing if extending `examples/latex-preamble.sty`:
- `scrbook` (KOMA-Script) needs `scrlayer-scrpage`, not `fancyhdr`, and
  `\setkomafont{...}` instead of `titlesec` — both `fancyhdr` and
  `titlesec` fight KOMA's internal page-style/heading machinery and throw
  "deprecated code" warnings on every compile.
- The `glossaries` package's `[toc]` option captures its ToC entry text
  before babel/translator's French translation takes effect, so it stays
  "Glossary" even though the printed heading correctly shows "Glossaire".
  Fix: pass `\printglossary[title=Glossaire, toctitle=Glossaire]`
  explicitly in `main.tex` rather than relying on that translation timing
  (already done in `examples/latex-main.tex`).
